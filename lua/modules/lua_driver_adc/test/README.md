# lua_driver_adc

Lua ADC driver for Ameba RTOS (RTL8721F). Uses fwlib raw API (`ADC_*`, pinmux,
PAD control) directly — no HAL layer. `require("adc")` returns a table with one
constructor; the constructor returns a **handle** (userdata object).

## API

All parameter orders verified line-by-line against `src/lua_driver_adc.c`.

```lua
local adc = require("adc")

-- Constructor
local ch = adc.new(pin1 [, pin2, ...] [, mode])
```

| Parameter | Type   | Description                                           |
|-----------|--------|-------------------------------------------------------|
| `pinN`    | string | Pin name, e.g. `"PA_13"`. 1–8 pins accepted.         |
| `mode`    | string | `"sw"` (default, SW-trigger) or `"auto"` (AUTO mode) |

Returns a handle. Raises if a handle is already open, if no pins are given, or if
a pin is not ADC-capable. Only one handle may be open at a time.

### Handle methods

```lua
-- SW-trigger mode (mode = "sw", default)
local t  = ch:read()            -- SW trigger, all channels, blocking
                                 -- returns {[hw_channel_id] = millivolts, ...}
ch:trigger([enable])            -- start (nil/true) or stop (false) non-blocking SW conversion
local ok = ch:readable()        -- true when ≥1 sample is in the FIFO
local id, raw = ch:read_raw()   -- pop one FIFO sample: ch_id (int) + raw 16-bit code
                                 -- returns nil when FIFO is empty

-- AUTO mode (mode = "auto")
local arr = ch:read_auto(count) -- read `count` samples (1..256) in AUTO mode
                                 -- returns array of {ch=hw_channel_id, mv=millivolts}

-- Lifecycle
ch:close()                      -- release ADC, gate RCC clock, restore pins to GPIO
                                 -- also called by GC on collection
```

### Pin → ADC channel mapping (RTL8721F)

| Pin    | ADC Channel |
|--------|-------------|
| PA_20  | CH0         |
| PA_19  | CH1         |
| PA_18  | CH2         |
| PA_17  | CH3         |
| PA_15  | CH4         |
| PA_14  | CH5         |
| PA_13  | CH6         |
| PA_12  | CH7         |

> PA_18 / PA_19 are shared with SWD. Use PA_13 / PA_14 / PA_20 for typical tests.

## Test

The test suite is `test/test_adc.lua`. It is embedded at build time into
`adc_test_lua.h` (generated by `lua_to_cstr.py`) and compiled into the firmware
via `test/lua_adc_test_provision.c`.

### Trigger commands

```
AT+CLAW=adc         run loopback test  (PA_13 ↔ PA_25, PA_14 ↔ PA_26 wired)
AT+CLAW=adc,ext     run external-supply test (external 0–3.3 V on PA_13, PA_14)
```

### Wiring

| Test mode     | Connections required                                       |
|---------------|------------------------------------------------------------|
| `loopback`    | PA_13 ↔ PA_25 (jumper), PA_14 ↔ PA_26 (jumper)           |
| `ext_supply`  | External 0–3.3 V source connected to PA_13 and PA_14      |

PA_25 and PA_26 are configured as GPIO outputs by the test to drive the ADC
inputs high or low. No external components are required for the loopback mode.

### Success criterion

The final output line is `[adc_test] success` when all phases pass, or
`[adc_test] FAIL` otherwise.

### Test cases

| Phase | Name                     | What it exercises                                                         |
|-------|--------------------------|---------------------------------------------------------------------------|
| Excl  | Exclusive single-instance| Second `adc.new()` rejected while handle is open; reopen after `close()` |
| 1     | SW trigger read() low    | `adc.new("PA_13","PA_14")`, GPIO=LOW, `read()` checks < 300 mV           |
| 1     | SW trigger read() high   | GPIO=HIGH, `read()` checks > 2800 mV                                     |
| 2     | read() ×10 rounds        | 10 consecutive `read()` calls at GPIO=LOW, each < 300 mV                 |
| 3     | trigger / readable / read_raw | `trigger()` → poll `readable()` → `trigger(false)` → drain `read_raw()` |
| 4     | AUTO mode low            | `adc.new(...,"auto")`, GPIO=LOW, `read_auto(20)` all < 300 mV            |
| 4     | AUTO mode high           | GPIO=HIGH, `read_auto(20)` all > 2800 mV                                 |

All seven APIs exercised: `new`, `read`, `trigger`, `readable`, `read_raw`,
`read_auto`, `close`.

## Concurrency & resources

**Resource model (init → operation → deinit):**

```
adc.new(pins...)   — enables RCC clock, configures pinmux, calls ADC_Init + ADC_Cmd
ch:read() / ...    — acquires s_adc_lock, performs conversion, releases lock
ch:close()         — ADC_Cmd(DISABLE), RCC disable, pinmux restored to GPIO
                     (GC also calls close() automatically)
```

The `close()` → `adc.new()` cycle is fully repeatable. **Phase Excl** verifies:
1. While a handle is open, a second `adc.new()` is rejected.
2. After `close()`, a fresh `adc.new()` with a different mode succeeds.

**Lock scope:**
Each API method (`read`, `trigger`, `readable`, `read_raw`, `read_auto`) acquires
`s_adc_lock` for the duration of the hardware operation. No lock is held across
calls. Argument validation and `luaL_error` / `lua_newuserdata` paths always run
**before** any lock is taken to prevent longjmp-induced mutex leaks.

**ISR:** not used in SW-trigger or AUTO mode. The FIFO is polled.

**Multi-step atomicity:**
A `trigger() → readable() → read_raw()` sequence spans multiple calls, so it is
**not atomic**. Two concurrent scripts running this flow against the same open
handle will race on the FIFO. Run ADC work in a single task when sequencing is
required.

**Single hardware instance:**
The ADC block has one channel list and one op-mode. Only one open handle is
permitted at a time (`s_adc_refcount` exclusive guard). Verify with Phase Excl.
