# 〈编号〉 〈用例名〉 — 测试规格

## 前置条件（Pre-condition）

| 项目 | 要求 |
|---|---|
| 固件 | ameba-claw 正在运行，串口可收到 `+CLAW:` 输出 |
| 网络 | 〈按需：设备已联网；可访问 xxx；allowlist 含 xxx〉 |
| Capability | 〈列出用到的 cap，如 `http_request`、`sync_time`、`web_search`、`display`〉已注册（`AT+CLAW=cap` 可见）|
| 外设 | 〈外设类才写：OLED/LCD/按键接好并共地；TESTER 板已连接〉 |
| VQA 脚本 | 〈外设类才写：把下文的 `<VQA_SCRIPT>` 替换成本机 vqa.sh 绝对路径（如 `bash /home/xxx/auto_perf/vqa.sh`）〉 |
| Skill 安装 | 〈若有 SKILL.md：`〈skill_name〉` 已安装到 `vfs:/skills/〈skill_name〉/`〉 |
| 初始状态 | 无其他 Lua async job 运行（`AT+CLAW=ask,请列出并停止所有正在运行的lua任务`）|

---

## 测试步骤（每轮）

### Step 1 — 清空会话

​```
AT+CLAW=session,clear,all
​```

### Step 2 — 下发任务（Prompt）

​```
AT+CLAW=ask,〈纯自然语言需求，只说要什么不说怎么做，绝不含 Lua / API / 函数名 / pin 配置代码〉
​```

等待串口出现 `FINAL iter=N`（约 〈30–60s / 3–10min〉）。

### Step 3 — 记录结果 + 第一轮验收

先记录：

| 数据 | 来源 |
|---|---|
| `FINAL iter=N`，N 值 | 串口日志 |
| 回复首行 / LLM 汇报的关键信息（如按键映射）| `+CLAW:` 串口输出 |
| 工具调用序列 | 串口 narration（`>> tool_call` 行）|

随即执行下方**验收点清单**，逐条判定 Pass/Fail。

### Step 4 — 问题回修循环（仅本轮验收有 Fail 时）

验收 Fail = claw 第一次没做好。通过 `AT+CLAW=ask` **只描述现象/哪条验收没过**，让它自己
诊断并修复。**⚠️ 只说现象，不说修法**——绝不提示根因 / Lua 写法 / API / pin 配置，否则等于
替它写代码，也会污染它的自我反思。修复后重跑失败的验收点。终止条件：全部必须项通过 →
进入 Step 5；或连续 3 次修不好 → 记为 finding，进入 Step 5。

### Step 5 — 自我汇报（每轮都执行）

> 不清 session，在验收+回修结束后、同一 session 内发送，让 LLM 回顾本轮完整上下文
>（含它第一次为什么没成功、第二次怎么改的）。
> **无论本轮 Pass 还是 Fail 都要做**——harness 障碍收集的主入口。

​```
AT+CLAW=ask,请回顾你刚才完成这个任务的过程，列出你遇到的所有问题和障碍：
工具调用失败、API不符合预期、文档缺失、文件系统限制、让你多花轮次的任何障碍。
请诚实详细汇报，这对改进系统很重要。
​```

等待完整回复（约 1–2 min）。原文记录汇报内容后再执行下一轮的 Step 1。

### Step 6 — Claude Code 研判 + 归档（CC 负责，非设备操作）

claw 自我汇报未必抓得住实质问题（可能漏报，或只把我们 Step 4 报的现象原样复述）。CC 必须
**独立研判、不照单全收**：核实每条真伪与根因层次（工具描述 / cap / driver / 文档 / Lua 层），
**只把复述现象、未真正诊断根因的降权**，并从 iter 轮次和失败日志里补漏。

研判/修复方法论见 [harness_test_skill.md](../../harness_test_skill.md) Step 6；**核实成立的
harness 改进点归档到 `test_report/`**（规范命名 `harness_report_<里程碑-分类>_<YYYYMMDD>.md`）。
详细报告/编译回测机制由"执行 test case"的流程统一规定，本 spec 不赘述。

## 整体 Pass 判定

| 条件 | 要求 |
|---|---|
| 〈必须验收点，如 A1–A3、B1〉通过 | 必须 |
| LLM iter 轮次 | ≤ 〈N〉 |
| 独立跑 3 次均通过 | 升 L1 必须 |

任意一项不通过 → 进入 Step 4 问题回修循环，最多 3 轮修复后重跑全部验收点。

## 使用提示

- 上面骨架里的 ​``` 是为了在本模板里转义展示，实际写入 test_spec.md 时用正常的三反引号。
- 纯网络/文本类：留 A/B(/C)，删外设的 VQA/GPIO 段。
- 外设类：留 VQA/GPIO 验收段，通常**不写** SKILL.md 引用行。
- 复杂 App（LLM 探索着建 App + 外设验收）：期望行为里写出探索链，验收点用 VQA/GPIO。
